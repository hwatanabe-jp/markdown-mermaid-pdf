# はじめに

本書は、行政機関等において Markdown を用いて文書を作成し、標準的な体裁の PDF 文書を自動生成するための技術的なポイントを提示するものである。

## 背景と目的

近年、行政機関等における文書作成業務では、文書の体裁調整に多くの時間が費やされており、本来注力すべき内容の検討・審査に十分な時間を確保できないことが課題となっている。また、文書の版管理が担当者の手作業に依存しているため、改定内容の追跡や過去の版の復元が困難となる事例も見受けられる。

こうした背景から、文書の内容と体裁を分離し、内容の記述に専念できる環境を整備することの重要性が高まっている。Markdown は、平易な記法で文書構造を表現できる軽量マークアップ言語であり、テキストファイルとして版管理システムとの親和性が高いことから、この課題に対する有力な選択肢の一つである。

本書は、Markdown を用いた文書作成を標準化するにあたって、変換方式の全体像を解説するとともに、文書構造の設計及び運用上の留意点を整理し、標準的な体裁の PDF 文書を安定的に生成するための考え方を提示することを目的とする。

## 適用対象

本書は、行政機関等において定型的な体裁を持つ報告書、ガイドライン等の文書を作成する業務を適用の対象とする。

## 位置付け

本書は、文書標準化に関する参考文書群の Informative（情報提供）のレベルの参考文書である。本書の内容は、各組織の実情に応じて取捨選択して活用することを想定している。

## 本書の構成

本書では、Markdown を用いた文書作成の標準化について解説する。具体的には、2章で、Markdown 文書から PDF 文書への変換方式の全体像を紹介し、標準化の対象となる範囲を明らかにする。続く3章では、文書作成における留意点を技術面及び運用面に分解し、それぞれにおける具体的な留意事項を紹介する。最後に、4章で本書の要点を総括する。

## 用語

本書において使用する用語は、表 1-1 及び本書に別段の定めがある場合を除くほか、一般的な技術用語の定義による。

| 用語 | 意味 |
|--------------|----------------------------------------|
| Markdown | 文書構造を平易な記法で表現する軽量マークアップ言語。見出し、箇条書き、表等を記号により記述する。 |
| フロントマター | Markdown 文書の冒頭に記載する、文書のメタデータを定義する領域。題名、日付等を YAML 形式で記述する。 |
| 自動組版 | 文書の内容と体裁の定義から、印刷可能な文書を機械的に生成する処理。 |
| 版管理 | 文書の変更履歴を記録し、任意の時点の内容を参照・復元可能とする管理手法。 |
| CI | Continuous Integration の略称。文書やソースコードに対する同時的な複数の変更を、継続的な検証によって品質を担保しながら自動的に取り込む考え方及び手順を指す。 |

# Markdown文書変換の概要

本章では、Markdown 文書から標準的な体裁の PDF 文書を生成する変換方式の全体像を解説し、標準化の対象となる構成要素を明らかにする。

## 変換方式の全体像

Markdown を用いた文書作成では、執筆者は文書の内容と構造のみを Markdown ファイルに記述し、体裁の定義は変換系があらかじめ保持する。変換系は、文書の構造を解析した上で、定義済みの体裁を適用して PDF 文書を生成する。図 2-1 は、この変換の流れを示したものである。

```{.mermaid caption="Markdown文書の変換の流れ"}
flowchart LR
    A[Markdown文書] --> B[構造解析]
    B --> C{スキーマ検証}
    C -->|適合| D[体裁の適用]
    C -->|不適合| E[エラー報告]
    D --> F[PDF文書]
```

この方式では、文書の体裁が変換系に集約されるため、執筆者ごとの体裁のばらつきが原理的に発生しない。また、同一の Markdown 文書から常に同一の PDF 文書が生成されるため、文書の再現性が担保される。

## 変換方式の重要性

文書の内容と体裁の分離は、次の観点から重要である。

- 執筆者が内容の記述に専念でき、体裁調整の作業が不要となる
- 組織全体で文書の体裁が統一され、文書の品質が安定する
- テキストファイルによる版管理が可能となり、変更履歴の追跡が容易となる
- 体裁の変更が生じた場合も、変換系の定義を更新するのみで全文書に反映できる

一方で、変換系が想定しない文書構造が入力された場合、意図しない体裁の文書が生成されるおそれがある。そのため、文書構造の規約をスキーマとして定義し、変換に先立って規約への適合を検証することが求められる。

# 文書作成における留意点

本章では、Markdown による文書作成を組織的に運用するにあたっての留意点を、技術面及び運用面に分けて解説する。

## 技術面での留意事項

### 文書構造の設計

文書構造の設計にあたっては、次の点に留意することが求められる。

#### 見出し階層の統一

見出しは、章、節、項の階層構造に従って記述し、階層の飛ばしを行わないこととする。階層の飛ばしが存在する文書は、目次の生成や体裁の適用において意図しない結果を生じさせる要因となる。

#### メタデータの記載

文書番号、日付、改定履歴等のメタデータは、フロントマターに集約して記載する。メタデータの記載例を次に示す。

```yaml
doc-number: TR-001
title: 文書の題名
date: 2026-07-15
organization: 発行組織の名称
revision-history:
  - date: 2026-07-15
    place: "-"
    description: ・初版決定
```

#### 図表の記述

図は Mermaid 記法等により文書中に記述し、画像ファイルの添付を最小限とする。表は Markdown の表記法により記述し、キャプションを付与する。

### 検証の自動化

文書構造の規約への適合は、人手による確認ではなく、変換系による機械的な検証によって担保することが重要である。検証すべき事項には、次のようなものがある。

1. 必須メタデータの記載の有無
2. 見出し階層の整合性
3. 図表キャプションの付与状況

表 3-1 は、検証事項と検出時の対応を整理したものである。

| 検証事項 | 検出時の対応 |
|--------------|------------------------------------|
| 必須メタデータの欠落 | 変換を中止し、欠落した項目名を明示してエラーを報告する |
| 見出し階層の飛ばし | 変換を中止し、当該見出しの位置と階層を明示してエラーを報告する |
| キャプションの欠落 | 警告を報告した上で、変換を継続する |

: 検証事項と検出時の対応

## 運用面での留意事項

### 版管理

文書の Markdown ファイルは、版管理システムで管理することを原則とする。版管理にあたっては、次の点に留意することが求められる。

- 改定の単位ごとに変更内容を記録し、改定履歴と対応付けること
- 公開した版には識別子を付与し、任意の時点の文書を復元可能とすること
- 文書の改定と PDF 文書の再生成を一体の手順として運用すること

### 継続的な検証

文書の変更を取り込む際には、CI により変換の成否を自動的に検証することが有効である[^1]。これにより、規約に適合しない文書が共有される事態を未然に防止できる。

[^1]: 例えば、版管理システムへの変更の登録を契機として変換処理を実行し、エラーの有無を確認する方法がある。

# まとめ

本書では、Markdown を用いた行政文書作成の標準化について、変換方式の全体像と文書作成における留意点を解説した。要点は次のとおりである。

- 文書の内容と体裁を分離し、体裁の定義を変換系に集約することで、文書の品質と再現性が担保される
- 文書構造の規約をスキーマとして定義し、機械的な検証により適合を担保することが重要である
- 文書の版管理と継続的な検証を組み合わせることで、組織的な文書作成業務の信頼性が向上する

各組織においては、本書で示した考え方を参考に、実情に応じた文書標準化の取組を進められたい。
