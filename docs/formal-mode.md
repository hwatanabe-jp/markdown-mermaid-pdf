# formal スタイル（お硬い文書モード）

`--style formal` を指定すると、デジタル庁の標準ガイドライン群風の体裁を持つ PDF 文書を生成できます。
このモードでは、Markdown 文書が本書のスキーマに適合していることを変換前に検証し、
適合しない場合は具体的なエラーメッセージとともに変換を中止します。

## 使い方

```bash
docker run --rm \
  -v $(pwd)/workspace:/workspace \
  ghcr.io/hwatanabe-jp/markdown-mermaid-pdf:latest \
  document.md output.pdf --style formal
```

`--style` を省略した場合（または `--style default`）は従来どおりの変換を行います。

## 生成される文書の構成

| ページ | 内容 |
|--------|------|
| 表紙 | シリーズ名・文書番号、題名、日付（和暦併記）、発行組織、枠囲みの文書情報（位置付け・キーワード・概要）。ページ番号なし |
| 改定履歴 | フロントマターの `revision-history` から生成される表。ページ番号なし |
| 目次 | 見出し3階層までを点線リーダー付きで掲載。このページからページ番号（フッター中央）が 1 で始まる |
| 本文 | 章ごとに改ページ。見出し・図表・脚注等に標準ガイドライン風の体裁を適用 |

## フロントマター（スキーマ）

文書冒頭の YAML フロントマターに、次の項目を記載します。

| 項目 | 必須 | 型 | 説明 |
|------|------|----|------|
| `doc-number` | ✓ | 文字列 | 文書番号（例: `DS-202`、`TR-001`） |
| `title` | ✓ | 文字列 | 文書の題名。複数行（YAML の `|` 記法）で書くと表紙の折返し位置を制御できる |
| `date` | ✓ | 文字列 | 発行日。`YYYY-MM-DD` 形式。「2026（令和8）年7月15日」の形式に自動変換される |
| `organization` | ✓ | 文字列 | 発行組織名（表紙に表示） |
| `revision-history` | ✓ | 配列 | 改定履歴。各要素は `date`（必須・`YYYY-MM-DD`）、`description`（必須）、`place`（任意・省略時 `-`）を持つ |
| `series` | - | 文字列 | 文書シリーズ名（表紙右上に文書番号とともに表示） |
| `version` | - | 文字列 | 作成者が指定する版（表紙・文書一覧に表示） |
| `status` | - | 文字列 | ドラフト等の状態（表紙・文書一覧に表示） |
| `subtitle` | - | 文字列 | 副題（表紙で題名の下に表示） |
| `position` | - | 文字列 | ドキュメントの位置付け（表紙の枠囲みに表示。複数行可） |
| `keywords` | - | 配列または文字列 | キーワード（表紙の枠囲みに読点区切りで表示） |
| `abstract` | - | 文字列 | 概要（表紙の枠囲みに表示） |

記載例:

```yaml
---
series: 文書標準化実践ガイドブック
doc-number: TR-001
title: |
  Markdownによる行政文書作成の標準化
  に関する技術レポート
date: 2026-07-15
organization: デジタル文書標準化推進室
position: |
  Informative
  参考とするドキュメント
keywords: [Markdown, 文書標準化, PDF]
abstract: |
  本書は、Markdown を用いた文書作成の標準化に向けて、
  変換方式の概要と運用上の留意点をガイドする。
revision-history:
  - date: 2026-07-15
    place: "-"
    description: ・初版決定
---
```

## 見出しの構造規則

| Markdown | 階層 | 体裁 |
|----------|------|------|
| `# 見出し` | 章 | 水色帯＋青文字。「1　題名」形式。章の前で自動改ページ |
| `## 見出し` | 節 | 青文字ゴシック。「1.1　題名」形式 |
| `### 見出し` | 項 | 青文字ゴシック。「1)　題名」形式（節ごとに連番） |
| `#### 見出し` | 細目 | 黒太字ゴシック。「ア　題名」形式（カタカナ連番。目次には掲載されない） |
| `# 見出し {-}` | 別紙等 | 中央揃え・黒太字。番号なしで目次に掲載。「別紙1　参考文献」等に使用 |

次の規則に適合しない文書はエラーになります。

- 見出しは 4 階層（`####`）まで
- 階層を飛ばさないこと(`#` の直下に `###` を置く等は不可)
- 本文は必ずいずれかの章（`#`）の配下に置くこと（最初の見出しより前に本文を書かない）
- 番号付きの章（`{-}` なしの `#`）が 1 つ以上あること

## 本文で使える要素

- **段落**: 行頭は自動的に一字下げされます
- **箇条書き・番号付きリスト**: 通常の Markdown 記法
- **表**: パイプ記法。表の直後に `: キャプション` を書くと「表 2-1　キャプション」の形式で表の上部に表示されます（章ごとの連番）。ヘッダー行はグレー地、全体は罫線付きになります
- **図（Mermaid）**: ` ```{.mermaid caption="キャプション"} ` と書くと「図 2-1　キャプション」の形式で図の上部に表示されます。
  formal スタイルでは印刷向けにコントラストの高い neutral テーマが既定です
  （ワークスペースに `.mermaid-config.json` を置けば上書きできます）
- **図（画像）**: `![キャプション](path.png)` も同様に扱われます
- **コードブロック**: 言語指定付きのフェンスは薄灰色の地・モノクロ表示になります
- **脚注**: `[^1]` 記法。ページ下部に罫線付きで表示されます
- **改ページ**: 章の前では自動改ページされます。任意の位置では `<!-- pagebreak -->` を使用できます

## エラーメッセージ

スキーマに適合しない場合、変換は非 0 の終了コードで中止され、
`[formal]` で始まるエラーメッセージに違反内容が列挙されます。

例:

```
[formal] スキーマ検証エラー:
- 必須メタデータ 'doc-number' がありません
- 見出し「検証の自動化」(3階層目) : 直前の見出し(1階層目)から階層が飛んでいます
```

## 再現の方針と制限事項

- デジタル庁「デジタル社会推進実践ガイドブック」等の公開文書の構成・書式・トーンを参考に、
  類似の体裁を再現するものです。特定の組織の公式文書であるかのような出力（ロゴ等）は行いません
- Word で作成された原本とのピクセル単位の一致は目標としません
- フォントはイメージ同梱の Noto Serif CJK JP（本文）と Noto Sans CJK JP（見出し）を使用します

## 文書一式の生成

マスタ文書と詳細文書をそれぞれ独立した PDF にするには、`--set` を使います。
この指定ではすべての文書に formal スタイルを適用します。

```bash
docker run --rm -v "$PWD/workspace:/workspace" \
  ghcr.io/hwatanabe-jp/markdown-mermaid-pdf:latest \
  --set formal-set/documents.json formal-set/dist
```

出力ディレクトリを省略すると、設定ファイルと同じディレクトリの `dist` に出力します。
出力先は**まだ存在しないディレクトリ**を指定してください。再生成する場合は別の出力先を
指定するか、以前の成果物を移動してから実行します。全件を検証し、一時ディレクトリ内で
すべての PDF の変換が成功したときだけ出力先を確定します。失敗時は非 0 終了となり、
対象文書と理由がログに出ます。作成途中の PDF は公開せず、一時ファイルを削除します。

### 設定ファイル

UTF-8 の JSON で、`documents` の配列順に一覧への掲載と変換を行います。

```json
{
  "documents": [
    { "id": "master", "input": "マスタ 文書.md", "output": "全体 構成.pdf" },
    { "id": "design", "input": "詳細 資料/設計.md", "output": "設計 詳細.pdf" },
    { "id": "operations", "input": "詳細 資料/運用.md", "output": "運用.pdf" }
  ]
}
```

- `id`: 参照用の固定 ID。英数字で始まり、英数字・`_`・`-` が使えます。
  文書番号とは独立しているため、文書番号を変えても参照の修正は不要です。
- `input`: 設定ファイルの位置を基準とする Markdown のパス。
  各 Markdown の画像は、その Markdown のディレクトリを基準に解決します。
- `output`: 出力 PDF のファイル名。日本語と空白を使用できます。
  一式は同じディレクトリに置き、サブディレクトリや `/ \ < > : " | ? * # %`、
  制御文字、先頭の `.` は使用できません。

ID・入力ファイル・文書番号・出力名の重複はエラーです。出力名の重複は、大文字小文字と
Unicode の正規化も考慮して検査します。設定に未知の項目がある場合もエラーになります。
タイトル・文書番号・版・状態は各 Markdown のフロントマターだけに記入します。

### 版と状態

任意の `version` と `status` を文字列で指定すると、表紙と文書一覧に表示します。
単一文書の `--style formal` でも使用できます。既存文書への追加は必須ではありません。
これらは作成者が指定する表示情報であり、承認やリリースを自動判定するものではありません。

```yaml
version: "1.0"
status: ドラフト
```

### 文書一覧の挿入

マスタ文書の章の配下に空の Div を配置します。一式に含まれる全件（マスタ自身を含む）を、
文書番号・タイトル・任意の版と状態を持つリンク付きの箇条書きに展開します。
複数箇所への挿入もできます。

```markdown
# 全体構成

## 文書一覧

::: {.document-list}
:::
```

### 文書・見出しの参照

`doc:ID` で文書全体、`doc:ID#見出しID` で見出しを参照します。
明示的な見出し ID を付けておくと、見出し名を変更しても参照が安定します。

```markdown
## 構成 {#architecture}

運用は [](doc:operations#procedure) を参照。

[運用仕様を開く](doc:operations)
```

- **表示文言が空**の `[](doc:design#architecture)` は、例えば
  `SET-002 設計仕様 — 1.1 構成` のように自動生成します。
  項・細目の参照では、上位の番号も含めて `1.1 1) ア 処理部` のように表示します。
- **表示文言がある**リンクは、その文言・強調などの書式を保持します。
  文言自体に手入力した章番号は自動更新されません。
- `# 別紙 連絡先 {#appendix .unnumbered}` のような番号なし見出しは、名前で参照できます。
- 文書構成の変更時は一式を再生成すると、番号と出力名がリンク・自動表示へ反映されます。
- 存在しない文書・見出しや重複した見出し ID はエラーです。
  `docset-h` に数字が続く ID は内部移動先用に予約されています。
  細目のカタカナ番号はテンプレートに合わせて各項20件までです。
- 通常の `[参考資料](reference.pdf)`、外部 URL、`[節](#section)` は対象文書間参照として
  変換・検査しません。外部サイトの到達性も検査しません。
  配布対象外の参考資料は別途配置してください。

### PDF ビューアと配布時の制約

別 PDF へのリンクは相対ファイル名と PDF の `GoToR` アクション、見出しへの移動は
名前付き移動先を使います。日本語ファイル名には Unicode のファイル指定（`/UF`）も埋め込みます。
PDF は出力ディレクトリごと配布し、生成後に個別のファイル名を変更しないでください。

対応対象は、ローカルファイル間の移動と名前付き移動先を扱えるデスクトップ版
Adobe Acrobat / Reader 等です。ただし、このリポジトリの自動テストは PDF 内の
リンク・移動先の構造を検査するもので、Acrobat の GUI 操作を検証してはいません。
ブラウザ内蔵ビューア・モバイル・メールのプレビューでは別ファイルへの移動が制限されることがあり、
同じ動作は保証しません。デスクトップでも閲覧ソフトのセキュリティ設定が適用されます。
移動できない環境や印刷物では、自動表示された文書番号・タイトル・見出し番号・名前から探せます。

仕様の参考: [hyperref マニュアル](https://tug.ctan.org/macros/latex/contrib/hyperref/doc/hyperref-doc.html)、
[Adobe Acrobat の外部コンテンツアクセス](https://www.adobe.com/devnet-docs/acrobatetk/tools/AppSec/external.html)。

### サンプルと検証

`workspace/formal-set/` にマスタ1冊と詳細2冊の例があります。`make example-set` で生成できます。
`make test` は従来の単一文書・Mermaid・改ページ検査に加え、一式の PDF 生成、相互参照、
見出し番号・出力名変更、重複・参照先エラー、途中失敗、日本語・空白を含むパス、
サブディレクトリの画像を検証します。
