# formal スタイル（お硬い文書モード）

`--style formal` を指定すると、デジタル庁の標準ガイドライン群風の体裁を持つ PDF 文書を生成できます。
このモードでは、Markdown 文書が本書のスキーマに適合していることを変換前に検証し、
適合しない場合は具体的なエラーメッセージとともに変換を中止します。

## 使い方

```bash
docker run --rm \
  -v $(pwd)/workspace:/workspace \
  ghcr.io/hwatanabe-jp/markdown-mermaid-pdf:latest \
  document.md output.pdf --style formal
```

`--style` を省略した場合（または `--style default`）は従来どおりの変換を行います。

## 生成される文書の構成

| ページ | 内容 |
|--------|------|
| 表紙 | シリーズ名・文書番号、題名、日付（和暦併記）、発行組織、枠囲みの文書情報（位置付け・キーワード・概要）。ページ番号なし |
| 改定履歴 | フロントマターの `revision-history` から生成される表。ページ番号なし |
| 目次 | 見出し3階層までを点線リーダー付きで掲載。このページからページ番号（フッター中央）が 1 で始まる |
| 本文 | 章ごとに改ページ。見出し・図表・脚注等に標準ガイドライン風の体裁を適用 |

## フロントマター（スキーマ）

文書冒頭の YAML フロントマターに、次の項目を記載します。

| 項目 | 必須 | 型 | 説明 |
|------|------|----|------|
| `doc-number` | ✓ | 文字列 | 文書番号（例: `DS-202`、`TR-001`） |
| `title` | ✓ | 文字列 | 文書の題名。複数行（YAML の `|` 記法）で書くと表紙の折返し位置を制御できる |
| `date` | ✓ | 文字列 | 発行日。`YYYY-MM-DD` 形式。「2026（令和8）年7月15日」の形式に自動変換される |
| `organization` | ✓ | 文字列 | 発行組織名（表紙に表示） |
| `revision-history` | ✓ | 配列 | 改定履歴。各要素は `date`（必須・`YYYY-MM-DD`）、`description`（必須）、`place`（任意・省略時 `-`）を持つ |
| `series` | - | 文字列 | 文書シリーズ名（表紙右上に文書番号とともに表示） |
| `subtitle` | - | 文字列 | 副題（表紙で題名の下に表示） |
| `position` | - | 文字列 | ドキュメントの位置付け（表紙の枠囲みに表示。複数行可） |
| `keywords` | - | 配列または文字列 | キーワード（表紙の枠囲みに読点区切りで表示） |
| `abstract` | - | 文字列 | 概要（表紙の枠囲みに表示） |

記載例:

```yaml
---
series: 文書標準化実践ガイドブック
doc-number: TR-001
title: |
  Markdownによる行政文書作成の標準化
  に関する技術レポート
date: 2026-07-15
organization: デジタル文書標準化推進室
position: |
  Informative
  参考とするドキュメント
keywords: [Markdown, 文書標準化, PDF]
abstract: |
  本書は、Markdown を用いた文書作成の標準化に向けて、
  変換方式の概要と運用上の留意点をガイドする。
revision-history:
  - date: 2026-07-15
    place: "-"
    description: ・初版決定
---
```

## 見出しの構造規則

| Markdown | 階層 | 体裁 |
|----------|------|------|
| `# 見出し` | 章 | 水色帯＋青文字。「1　題名」形式。章の前で自動改ページ |
| `## 見出し` | 節 | 青文字ゴシック。「1.1　題名」形式 |
| `### 見出し` | 項 | 青文字ゴシック。「1)　題名」形式（節ごとに連番） |
| `#### 見出し` | 細目 | 黒太字ゴシック。「ア　題名」形式（カタカナ連番。目次には掲載されない） |
| `# 見出し {-}` | 別紙等 | 中央揃え・黒太字。番号なしで目次に掲載。「別紙1　参考文献」等に使用 |

次の規則に適合しない文書はエラーになります。

- 見出しは 4 階層（`####`）まで
- 階層を飛ばさないこと(`#` の直下に `###` を置く等は不可)
- 本文は必ずいずれかの章（`#`）の配下に置くこと（最初の見出しより前に本文を書かない）
- 番号付きの章（`{-}` なしの `#`）が 1 つ以上あること

## 本文で使える要素

- **段落**: 行頭は自動的に一字下げされます
- **箇条書き・番号付きリスト**: 通常の Markdown 記法
- **表**: パイプ記法。表の直後に `: キャプション` を書くと「表 2-1　キャプション」の形式で表の上部に表示されます（章ごとの連番）。ヘッダー行はグレー地、全体は罫線付きになります
- **図（Mermaid）**: ` ```{.mermaid caption="キャプション"} ` と書くと「図 2-1　キャプション」の形式で図の上部に表示されます。
  formal スタイルでは印刷向けにコントラストの高い neutral テーマが既定です
  （ワークスペースに `.mermaid-config.json` を置けば上書きできます）
- **図（画像）**: `![キャプション](path.png)` も同様に扱われます
- **コードブロック**: 言語指定付きのフェンスは薄灰色の地・モノクロ表示になります
- **脚注**: `[^1]` 記法。ページ下部に罫線付きで表示されます
- **改ページ**: 章の前では自動改ページされます。任意の位置では `<!-- pagebreak -->` を使用できます

## エラーメッセージ

スキーマに適合しない場合、変換は非 0 の終了コードで中止され、
`[formal]` で始まるエラーメッセージに違反内容が列挙されます。

例:

```
[formal] スキーマ検証エラー:
- 必須メタデータ 'doc-number' がありません
- 見出し「検証の自動化」(3階層目) : 直前の見出し(1階層目)から階層が飛んでいます
```

## 再現の方針と制限事項

- デジタル庁「デジタル社会推進実践ガイドブック」等の公開文書の構成・書式・トーンを参考に、
  類似の体裁を再現するものです。特定の組織の公式文書であるかのような出力（ロゴ等）は行いません
- Word で作成された原本とのピクセル単位の一致は目標としません
- フォントはイメージ同梱の Noto Serif CJK JP（本文）と Noto Sans CJK JP（見出し）を使用します
